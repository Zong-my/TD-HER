# Binding extension protocols to your own runs

The files ending in .template.json are design templates, not populated result manifests.
Copy the relevant template to TDHER_WORKDIR/protocols, remove .template from its name,
and fill the fields below from your own upstream artifacts. Do not copy historical
author result tables, fitted settings, cohort counts or checkpoint hashes into this repository.
Pass a different complete file with --protocol if needed.

## Published-predictor comparisons

Both drivers use the common-cohort interface under analytical/shared:
event_index.csv, eval_truth/truth_v1/target_compatibility.csv, and
analytical/physical_causal_sfr_fnp_v2/analytical_predictions.csv.
These files are generated by your own preprocessing/analytical evaluation, not supplied data.
The analytical implementation and equipment-conditioned fitting configuration are included.

Set evaluation.common_cohort.source_files to their absolute external paths.
Set expected_counts to your declared L1/L2/L3 common-cohort sizes. Define these from input
identity and applicability, before comparing learned test predictions. The driver asserts
unique, in-range cohort indices and the declared sizes. Leave printed_references_frozen empty
unless you independently supply an explicitly identified reference record outside this tree.

For FNP-BPNN also bind extraction.raw_pools and extraction.splits to your raw workbook pools.
Analytical equipment mapping requires analytical/adaptation_v1/results_sav_v2/
sav_bound_case_map.json with the unit records consumed by operational_inputs.py and
governor_models.py. Obtain it from the corresponding licensed case inputs, retaining bus,
machine, inertia, base-MVA and governor parameters. Do not substitute the mixed-resource
case for the original benchmark case. Build the equipment-conditioned bank with
build_fnp_conditioned_bank.py; it writes only to the external analytical workspace.

## Widened PatchTST

First train the base PatchTST and execute the capacity-control configuration stage.
Fill published_configuration with the five training/validation-selected fields from your
own upstream base expert and matching control protocol. This legacy field name identifies
the fixed reference configuration; it does not mean an author-fitted parameter file is shipped.
The driver verifies equality with these two upstream records.
The supplied search budget is 20 trials. Search and robustness phases do not read test arrays.

## Second ConvLSTM backbone

Bind frozen_sources.convlstm_expert.best_params.path to your own external best_params.json,
and sha256 to that file's checksum. Copy its optimizer settings into backbone_configuration.
Build model_kwargs using the selected architecture and your data dimensions, exactly as
backbone_config() derives them in exp_v4_second_backbone_convlstm.py.
Set expected_parameter_count for that architecture, and outputs.root/smoke_root to absolute
external directories. MMoE head field names follow the runner's model constructor.
The runner rejects a mismatched source hash, architecture or optimizer binding.

These additional drivers are research workflows with explicit upstream manifests, not a
one-command replay of precomputed author results. Their --help and source validation routines
describe the required interfaces. The release smoke checks exercise imports and CLI parsing;
they do not claim execution of these studies.
